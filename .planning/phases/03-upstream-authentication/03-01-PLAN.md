Create internal/config package with ExpandEnvWithValidation function:

1. Use regexp `\$\{([A-Za-z0-9_]+)\}` to find all ${VAR} references
2. For each match, call os.LookupEnv to check existence
3. If variable not set OR empty, return error with variable name
4. Only after all validated, call os.ExpandEnv to expand

Per RESEARCH.md Pitfall 1: os.ExpandEnv silently returns empty string for undefined vars.
This function MUST validate BEFORE expanding.

Test cases:
- Valid: "${FOO}" with FOO=bar -> "bar"
- Missing var: "${MISSING}" -> error "environment variable MISSING is not set"
- Empty var: "${EMPTY}" with EMPTY="" -> error "environment variable EMPTY is empty"
- Multiple vars: "${A}/${B}" with A=x, B=y -> "x/y"
- No vars: "literal" -> "literal"
  </action>

Create internal/auth package with Strategy interface and Config types:

```go
// Strategy represents an upstream authentication strategy.
type Strategy interface {
    // RoundTripper returns an http.RoundTripper that injects authentication.
    RoundTripper(base http.RoundTripper) http.RoundTripper
}

// Config represents auth configuration from YAML (exactly one strategy per upstream).
type Config struct {
    Header      *HeaderConfig      `yaml:"header"`
    Basic       *BasicConfig       `yaml:"basic"`
    Passthrough *PassthroughConfig `yaml:"passthrough"`
    OAuth2      *OAuth2Config      `yaml:"oauth2"`
}

// HeaderConfig for static header injection (AUTH-01).
type HeaderConfig struct {
    Name  string `yaml:"name"`  // Header name (e.g., "X-API-Key")
    Value string `yaml:"value"` // Value with ${VAR} syntax
}

// BasicConfig for HTTP Basic Auth (AUTH-02).
type BasicConfig struct {
    Username string `yaml:"username"` // Username with ${VAR} syntax
    Password string `yaml:"password"` // Password with ${VAR} syntax
}

// PassthroughConfig for forwarding client Authorization header (AUTH-03).
type PassthroughConfig struct {
    // No fields - presence indicates passthrough mode
}

// OAuth2Config for OAuth2 client credentials flow (AUTH-04, AUTH-05).
type OAuth2Config struct {
    TokenURL     string   `yaml:"token_url"`
    ClientID     string   `yaml:"client_id"`     // With ${VAR} syntax
    ClientSecret string   `yaml:"client_secret"` // With ${VAR} syntax
    Scopes       []string `yaml:"scopes"`        // Optional
}
```

Add Validate() method to Config that returns error if multiple strategies defined (mutual exclusivity per CONTEXT.md).

Add NoneStrategy as default (no auth, base RoundTripper passthrough).
