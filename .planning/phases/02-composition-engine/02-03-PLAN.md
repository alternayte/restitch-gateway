Create step execution module that makes HTTP requests to upstreams.

**step.go:**
```go
// StepResult holds the response from an upstream service
type StepResult struct {
    Status  int
    Headers http.Header
    Body    interface{} // Parsed JSON body as map[string]interface{} or []interface{}
    RawBody []byte      // Original response body
}

// ExecuteStep executes a single step by making HTTP request to upstream
func ExecuteStep(ctx context.Context, step *CompiledStep, upstream *Upstream, env map[string]interface{}, httpClient *http.Client) (*StepResult, error)
```

**Implementation:**

1. **Evaluate expressions for request:**
   - Evaluate step.PathExpr with current env to get actual path
   - Evaluate step.BodyExpr if present (for POST/PUT)
   - Evaluate each header expression

2. **Build HTTP request:**
   - Construct URL: upstream.URL + evaluated path
   - Use step.Method (defaulted to GET during parsing)
   - Set evaluated headers
   - Use http.NewRequestWithContext(ctx, ...) - CRITICAL for cancellation per RESEARCH.md Pitfall 7

3. **Header propagation per CONTEXT.md:**
   - Auto-propagate from incoming request: X-Request-ID, X-Correlation-ID, traceparent, Accept, Accept-Language
   - Generate UUID for X-Request-ID if not present in env

4. **Execute request:**
   - Use provided httpClient (Phase 1's client with connection pooling)
   - Handle response: read body, parse JSON
   - ALWAYS drain response body using Phase 1's DrainAndClose pattern (RESEARCH.md Pitfall 1)

5. **Error handling per CONTEXT.md:**
   - Upstream error passthrough: return upstream's status code and body directly
   - Only return error if network failure or context cancelled
   - Non-2xx status is NOT an error in Phase 2 (all steps required, error handling is Phase 4)

**Helper functions:**

Create composition executor that runs steps according to DAG execution plan.

**executor.go:**
```go
// CompositionResult holds results from all steps
type CompositionResult struct {
    Steps map[string]*StepResult
}

// Executor runs compositions
type Executor struct {
    config     *CompiledConfig
    httpClient *http.Client
}

// NewExecutor creates a new composition executor
func NewExecutor(config *CompiledConfig, httpClient *http.Client) *Executor

// Execute runs a composition for an incoming request
func (e *Executor) Execute(ctx context.Context, compositionName string, req *http.Request) (*CompositionResult, error)
```

**Implementation using errgroup (per RESEARCH.md Pattern 3):**

1. **Get composition and execution plan:**
   - Look up composition by name
   - Get pre-built ExecutionPlan from DAG

2. **Execute wave by wave:**
   ```go
   results := make(map[string]*StepResult)
   resultsMutex := sync.Mutex{}

   for _, wave := range plan.Waves {
       g, waveCtx := errgroup.WithContext(ctx)

       for _, stepName := range wave {
           stepName := stepName // Capture loop variable
           step := comp.Steps[stepName]

           g.Go(func() error {
               // Build env with current results
               resultsMutex.Lock()
               env := buildRequestEnv(req, results)
               resultsMutex.Unlock()

               // Execute step
               result, err := ExecuteStep(waveCtx, step, upstream, env, e.httpClient)
               if err != nil {
                   return fmt.Errorf("step %s: %w", stepName, err)
               }

               // Store result
               resultsMutex.Lock()
               results[stepName] = result
               resultsMutex.Unlock()

               return nil
           })
       }

       // Wait for wave to complete or first error
       if err := g.Wait(); err != nil {
           return nil, err // Fail fast - context cancelled remaining goroutines
       }
   }
   ```

3. **Logging per CONTEXT.md:**
   - Log step start/complete events at normal level
   - Include step name, upstream URL, duration
   - Log full DAG plan at debug level (optional for Phase 2)

**Key implementation notes:**
- errgroup.WithContext creates derived context - cancellation propagates
- resultsMutex protects concurrent map access
- Each wave completes before next wave starts
- First error in any wave cancels all goroutines in that wave
