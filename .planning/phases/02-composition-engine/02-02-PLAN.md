
**Implementation per RESEARCH.md Pattern 2:**
- Use expr parser to get AST: `parser.Parse(exprStr)`
- Walk AST with visitor pattern looking for `steps.X` patterns
- Handle both direct access (steps.user) and nested access (steps.user.body)
- Return deduplicated list of step names

**AST Visitor implementation:**
```go
type dependencyVisitor struct {
    dependencies map[string]struct{}
}

func (v *dependencyVisitor) Visit(node *ast.Node) {
    // Look for MemberNode where Node is "steps" identifier
    if member, ok := (*node).(*ast.MemberNode); ok {
        if ident, ok := member.Node.(*ast.IdentifierNode); ok {
            if ident.Value == "steps" {
                // Extract step name from property
                if prop, ok := member.Property.(*ast.StringNode); ok {
                    v.dependencies[prop.Value] = struct{}{}
                }
                // Also handle identifier property access (steps.user vs steps["user"])
                if prop, ok := member.Property.(*ast.IdentifierNode); ok {
                    v.dependencies[prop.Value] = struct{}{}
                }
            }
        }
    }
}
```

Create DAG builder that produces an execution plan from compiled composition.

**dag.go:**
```go
// ExecutionPlan represents the order in which steps should execute
// Steps in the same wave can run in parallel
type ExecutionPlan struct {
    Waves [][]string // Each wave contains step names that can run in parallel
}

// BuildDAG analyzes a composition and produces an execution plan
// Returns error if circular dependency detected
func BuildDAG(comp *CompiledComposition) (*ExecutionPlan, error)
```

**Implementation using Kahn's algorithm (per RESEARCH.md Pattern 6):**

1. **Build dependency graph:**
   - For each step, extract dependencies from all expressions (path, body, headers)
   - Merge with explicit depends_on from config
   - Build inDegree map and edges map

2. **Validate references:**
   - All dependency step names must exist in composition
   - Return error if step references non-existent step

3. **Topological sort with level detection:**
   - Initialize queue with steps having inDegree=0 (no dependencies)
   - Process level by level, decrementing inDegree
   - Steps ready at same time = same wave (parallel execution)

4. **Cycle detection:**
   - After algorithm completes, verify all steps placed in waves
   - If some steps remain (inDegree > 0), cycle exists
   - Return descriptive error identifying cycle participants

**Helper functions:**
```go
// AnalyzeDependencies extracts all dependencies for a step from its expressions

// ValidateDependencies checks all referenced steps exist
func ValidateDependencies(steps map[string]*CompiledStep, deps map[string][]string) error
```

- Diamond: A -> C, B -> C produces waves [[A, B], [C]]
