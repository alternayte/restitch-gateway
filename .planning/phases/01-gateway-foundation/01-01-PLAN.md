<task type="auto">
  <name>Task 2: Create HTTP server with path and method routing</name>
  <files>
    internal/server/server.go
    internal/server/router.go
    cmd/restitch/main.go
  </files>
  <action>
Create server.go:
- `Server` struct holding: http.Server, router, config, ready state (atomic.Bool)
- `New(config Config) *Server` constructor
- `ListenAndServe() error` - starts HTTP server on configured port
- Server must use `http.Server` with proper timeouts:
  - ReadTimeout: 30s
  - WriteTimeout: 30s
  - IdleTimeout: 120s
- Store the http.Server for later graceful shutdown

Create router.go:
- `Router` struct with route registration
- `NewRouter() *Router`
- `Handle(method string, pattern string, handler http.HandlerFunc)`
- `ServeHTTP(w http.ResponseWriter, r *http.Request)` implementing http.Handler
- Route matching: exact path match first, then pattern match (simple prefix for now)
- Method matching: if route specifies method, only match that method
- Return 404 for unmatched paths, 405 for wrong method on matched path

Routing requirements (GATE-01, GATE-02):
- Support registering handlers for specific path + method combinations
- Path patterns: exact match (e.g., "/health") and prefix match (e.g., "/api/")
- Method filtering: GET, POST, PUT, DELETE, PATCH, OPTIONS
- Default 404 handler for unmatched routes
- Default 405 handler when path matches but method doesn't

Update main.go:
- Import and use server.New()
- Register a test route: GET /ping returns "pong" (for verification)
- Call ListenAndServe()

Do NOT implement TLS yet (Task 3). HTTP only for now.
  </action>
  <verify>
`go build ./cmd/restitch` succeeds
`./cmd/restitch/restitch &` starts server
`curl http://localhost:8080/ping` returns "pong" with 200
`curl http://localhost:8080/notfound` returns 404
`curl -X POST http://localhost:8080/ping` returns 405 (method not allowed)
Kill server after testing
  </verify>
  <done>
HTTP server starts on configured port, routes requests by path pattern and HTTP method, returns appropriate status codes for unmatched routes
  </done>
</task>

- `LoadTLSConfig(certFile, keyFile string) (*tls.Config, error)`
- Configure TLS with modern settings:

  - CurvePreferences: tls.CurveP256, tls.X25519
  - PreferServerCipherSuites: true (though deprecated, set for clarity)
- Return error if cert/key files don't exist or are invalid

Update server.go:
- Add `ListenAndServeTLS(certFile, keyFile string) error` method
- Create second http.Server for TLS on tls-port
- Both servers share the same router

Update main.go:
- Add --cert and --key flags for TLS certificate paths
- If cert/key provided, start both HTTP and TLS servers concurrently
- If cert/key not provided, only start HTTP server (with info log)
- Use goroutines to run both servers

For testing, generate self-signed cert:
```bash
openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -days 365 -nodes -subj "/CN=localhost"
```
